# 4.3. Prototipado de Interfaz

## 4.3.1. Interfaz de Autenticacion JWT y Acceso Seguro al Sistema

**Subtitulo Academico:** 4.3.1. Interfaz de Autenticacion JWT y Acceso Seguro al Sistema.

**Descripcion Funcional y Experiencia Humana (UX):** La pantalla de autenticacion cumple la funcion de puerta de entrada al sistema logistico minero, asegurando que solo usuarios registrados puedan acceder a informacion sensible sobre insumos, inventario, pedidos, compras y despachos. La composicion visual utiliza una paleta oscura con acentos azul y cian, asociada a seguridad, tecnologia y operacion industrial, lo cual establece continuidad grafica con el resto de la plataforma. El formulario se presenta con campos amplios, centrados y de alta legibilidad para reducir errores de digitacion en usuarios administrativos u operativos que pueden ingresar al sistema en horarios de alta demanda o durante cambios de turno. La pantalla evita sobrecargar al usuario con informacion secundaria y concentra la atencion en dos datos criticos: usuario y contrasena.

**Elementos Clave e Interaccion en el Prototipo (UI):** La interfaz incorpora campos de texto para usuario y contrasena, botones de visualizacion u ocultamiento de credenciales, mensaje de error y boton principal de ingreso. Al hacer clic en el boton de visibilidad, el campo alterna entre texto visible y protegido, permitiendo corregir errores sin exponer permanentemente la informacion. Al hacer clic en "Ingresar al sistema", el formulario valida campos obligatorios y ejecuta el endpoint `POST /auth/login`; si las credenciales son correctas, el prototipo almacena el token JWT y redirige al usuario al dashboard. Durante la validacion se activa el estado "Validando acceso...", lo que comunica que la operacion se encuentra en proceso y evita multiples envios. Si el backend responde con error, la pantalla presenta un mensaje claro de credenciales incorrectas, validando visualmente el mecanismo de autenticacion definido en la API REST.

## 4.3.2. Interfaz Contenedora de Navegacion Operativa y Sesion Activa

**Subtitulo Academico:** 4.3.2. Interfaz Contenedora de Navegacion Operativa y Sesion Activa.

**Descripcion Funcional y Experiencia Humana (UX):** La estructura base del sistema organiza la experiencia de uso mediante un panel lateral oscuro y un encabezado superior claro. Esta division permite separar la navegacion permanente de las tareas operativas, reduciendo la carga cognitiva del usuario al mantener siempre visibles los modulos principales. La agrupacion por categorias, como principal, administracion, catalogos, operacion logistica y seguimiento, responde a la logica de trabajo de una operacion minera: primero se consulta el estado general, luego se administran recursos, se ejecutan procesos logisticos y finalmente se revisan evidencias. El estado activo del menu evita desorientacion, especialmente cuando el usuario cambia rapidamente entre pedidos, inventario y compras.

**Elementos Clave e Interaccion en el Prototipo (UI):** La interfaz contiene menu lateral, enlaces con estado activo, encabezado institucional, contador de notificaciones, avatar con iniciales y menu de usuario. Al hacer clic en una opcion del menu, Angular Router carga el componente correspondiente dentro del contenedor principal. Los elementos visibles del menu se calculan segun permisos, por lo que la interfaz valida visualmente el modelo RBAC antes de que el usuario intente una accion no autorizada. El interceptor HTTP adjunta el encabezado `Authorization: Bearer <token>` a las solicitudes protegidas; si el backend devuelve `401`, la sesion se cierra y se redirige al login. Al hacer clic en el avatar, se despliega el menu de perfil y cierre de sesion; al cerrar sesion, se elimina el token local y se interrumpe el acceso a rutas protegidas.

**Elementos Clave e Interaccion en el Prototipo (UI):** Al hacer clic en "Actualizar perfil", la interfaz ejecuta `GET /auth/perfil`, protegido por JWT y permiso `perfil.ver`. La respuesta actualiza el estado local de autenticacion, garantizando que el encabezado, el menu y la informacion del perfil reflejen los datos mas recientes del backend. Los campos se presentan como bloques informativos y no como entradas editables, reduciendo el riesgo de modificar identidad, rol o area desde un flujo no autorizado. El estado activo o inactivo se representa con color, permitiendo validar visualmente la condicion administrativa de la cuenta autenticada.

## 4.3.16. Interfaz de Acceso Denegado por Control de Permisos

**Subtitulo Academico:** 4.3.16. Interfaz de Acceso Denegado por Control de Permisos.

**Descripcion Funcional y Experiencia Humana (UX):** La pantalla de acceso denegado cumple una funcion preventiva dentro de la experiencia de usuario: informar que el rol actual no tiene permiso para acceder a un modulo o accion. En lugar de presentar un error tecnico, el sistema comunica una causa funcional comprensible y ofrece retorno al dashboard. Esto reduce frustracion, evita interpretaciones erroneas sobre fallas del sistema y refuerza la separacion de responsabilidades. En un ambiente minero, donde diferentes usuarios participan en solicitudes, aprobaciones, inventario, compras y auditoria, este mensaje evita que personal no autorizado intente operar procesos sensibles.

**Elementos Clave e Interaccion en el Prototipo (UI):** La interfaz presenta codigo `403`, mensaje explicativo y enlace de retorno al dashboard. Su activacion se produce cuando el `permissionGuard` detecta ausencia de permisos requeridos en la ruta solicitada. Al hacer clic en "Volver al dashboard", el usuario retorna a una zona autorizada y puede continuar con las funciones disponibles para su rol. Esta pantalla valida visualmente la relacion entre frontend y API REST: aunque el menu ya oculta opciones no autorizadas, la ruta protegida mantiene una segunda capa de control, coherente con los decoradores `RequirePermissions` y la autenticacion JWT del backend.
